## 3. 三种推进路线

| 路线                    | 首先解决的问题                     | 优点                               | 代价与取舍                       |
| ----------------------- | ---------------------------------- | ---------------------------------- | -------------------------------- |
| A：写前回顾（已选方向） | 隔天回来不知道上次写到哪里         | 高频使用，也为后续检查提供来源资料 | 必须处理摘要过期和未确认内容     |
| B：交稿检查             | 写完后发现设定冲突与线索遗漏       | 问题与原文对应，收益容易感知       | 没有可靠事实与时间边界时误报较多 |
| C：连载计划             | 不清楚待写章节、可用存稿和更新安排 | 核心功能无需模型，结果确定         | 无法直接解决人物和情节遗忘       |

推荐顺序：先建立 A 的最小闭环，再在已确认资料上扩展 B；C 保持轻量，按真实连载习惯加入。

## 5. 首期方案：写前回顾

### 5.1 用户故事

1. 作为隔天继续连载的作者，我希望打开当前章节时看到前文摘要，以便快速恢复故事状态。
2. 作为同时维护多条故事线的作者，我希望看到与本章相关的人物状态，以便避免使用未来状态。
3. 作为容易在写作途中产生新想法的作者，我希望把未完成线索记录到作品中，以便下次接着处理。
4. 作为修改过前文的作者，我希望系统标明已过期的摘要，以便不把旧剧情当成当前事实。
5. 作为使用 AI 的作者，我希望先看候选摘要并核对出处，再决定是否保存为回顾资料。
6. 作为不使用 AI 的作者，我希望可以手工填写回顾资料，并在模型不可用时继续阅读和编辑。
7. 作为注重伏笔与悬念的作者，我希望回顾遵守当前章节的范围，以免把后续计划混入已经发生的剧情。
8. 作为有未保存正文的作者，我希望查看回顾不会丢掉草稿；跳转原文时沿用现有未保存保护。

### 5.2 建议用户流程

1. 在现有写作上下文面板中提供“写前回顾”页签，与 AI 助手、规划设定复用面板位置；不增加永久侧栏。入口位置仍待设计确认。
2. 默认展示当前章之前已确认的前情摘要、本章显式关联人物的已确认状态、作者记录的未完成线索。当前章尚无关联时给出选择入口。
3. 已有资料直接读取，不因打开面板自动调用模型。没有摘要时提供手工填写和“生成摘要候选”两个入口。
4. 首期建议从作者选定的单章生成摘要；列清输入章节和版本，生成结果单独预览，作者修改并确认后保存。已有长篇的批量回顾初始化另作后续能力。
5. 回顾中的条目显示来源章节及资料状态；点击来源打开对应章节，无法可靠定位旧段落时提示来源已变化，不跳到无关位置。
6. 作者可记录“下次写作接续点”，例如“下章开头先处理证人的矛盾证词”，并关联章节；它是创作计划，不自动作为已发生事实发送给 AI。

### 5.3 首期边界

- 首期聚焦 LC-01～LC-05 的最小范围：回顾展示、章节摘要、轻量人工确认记录、手工线索与输入清单；单章起步是建议，批量初始化是否纳入仍待确认。
- 暂不引入全书向量检索、自动人物关系图、复杂虚构历法、全书自动矛盾判定或长时间后台批量生成。
- 不把摘要文本直接追加到现有人物简介中；两者来源和生命周期不同。
- 不要求作者先整理全书才能使用；第一条手工摘要或线索即可进入回顾。
- 不自动提取并保存人物事实。结构化提取需要单独候选审核，不能复用“替换正文”来模拟入库。
- 首期不提供“继续生成下一章”自动调用；回顾的直接目标是帮助作者继续写作。

### 5.4 逐项验收建议

#### LC-01 写前回顾

- 作者从章节进入回顾后，应能看到前情、人物状态和未完成线索三个明确区域；没有内容时说明缺失项并提供添加入口。
- 回顾必须区分已确认、待确认、来源过期和创作计划，不能只靠颜色表达。
- 打开、切换和关闭回顾不得触发模型计费或覆盖正文；窄屏沿用抽屉，Escape 关闭后归还焦点。

#### LC-02 章节摘要

- 摘要必须关联作品、来源章节、来源版本、生成方式及确认状态；AI 摘要初始为候选，作者可修改、确认或丢弃。
- 来源版本变化后，旧摘要应标为过期；更新失败必须保留旧摘要并显示其状态，不能伪装成最新。
- 正文在生成过程中发生变化时，候选仍保留，但不得直接确认成当前版本摘要。重新生成或人工复核是明确操作。

#### LC-03 事实与人物状态

- 首期允许作者为本章关联人物记录简短状态，如地点、伤势、目标；应关联来源章节和适用剧情位置，支持手工记录。
- “计划加入的设定”“AI 推测”“作者确认的事实”应分别标识；前两者不得自动进入事实区。
- 相互冲突的记录不得静默覆盖；来源缺失或过期时显示异常，作者决定修正、保留或移除。

#### LC-04 未完成线索

- 作者可记录标题、简短说明、关联章节与状态，并标记已处理或暂不处理；首期不强制填写预计回收章。
- 作者应能从写作位置快速添加一条线索，操作完成后仍保留原有正文草稿。
- 线索状态由作者决定；模型可以提出候选，不能因为正文出现相似词语就自动认定已回收。

#### LC-05 上下文清单

- 生成前展示实际选定的章节、摘要、人物/设定及 Skill；来源失效或无访问权时拒绝使用，不能跨作品补全。
- 显示估算输入用量并明确“估算”；预算不足时让作者缩小范围，不静默截断，也不默认发送完整作品。
- 完整正文和上下文预览只在作者有权限的业务界面中展示，不进入日志或审计快照；不能把可见清单误作新增敏感日志。

### 5.5 如何判断首期有用

建议用作者本人的长篇进行人工试用，正式阈值在记录基线后再确定：

- 对比“隔天打开作品到能够继续写作”的用时，记录回顾是否减少翻章。
- 观察作者能否指出一条当前人物状态与一条未完成线索的来源。
- 统计因摘要过期导致的误用、作者改正 AI 摘要的次数和每次恢复上下文的模型调用次数。
- 摘要采纳率只用于观察负担，不能代替事实正确性；“打开面板次数”不能单独作为成功指标。
- 不默认采集正文、写作内容或用户行为遥测；先采用自愿试用记录和脱敏标量。

## 7. 实现与数据决策草案

本节是待评审方向，不预先确定路由、字段命名或完整 Schema。

- 优先复用作品所有权、章节版本、人物/设定关联、AI 任务与候选生命周期。
- 章节摘要、事实记录和未完成线索作为作品业务数据；版本过期检查必须在服务端完成，不能只依赖界面提示。
- 章节摘要与事实记录应引用来源文档及版本；事实另有剧情适用范围，不能把数据库修改时间当成故事时间。
- 来源为当前正文选区时，先沿用已有保存与版本保护。首期不解决任意编辑后仍永久稳定的段落锚点；定位失败要明确退回到章节。
- 新增表必须具有非空创建/更新时间及简体中文注释；迁移、模型与数据库文档同步。
- Web API 执行作品所有权与同作品关联检查。Desktop 后续通过窄 IPC 和本地 SQLite 实现相同业务语义，不让 renderer 访问数据库或密钥。
- 不因预期未来复用而提前建立跨端通用数据层或向量数据库。
- AI 结果先校验结构、来源和版本，再进入可审核候选；审核记录与最终事实分开，不能把未经确认的 AI 输出默认为事实。

## 8. 验证决策草案

### 用户流程验收入口

优先从“打开章节 → 查看回顾 → 打开来源 → 修改前文 → 看到过期状态 → 确认更新”这一条用户流程验证。检查用户实际看到的资料与实际保存的结果，不用组件内部状态断言代替验收。

### 必要测试边界

- API 集成：摘要候选生成与确认、来源版本变化、同作品关联、跨用户读取/写入拒绝、来源归档或删除、失败不覆盖已确认记录。
- Web 组件/流程：初始空状态、已有摘要、模型失败、候选拒绝、未保存保护、过期标识、三语言、键盘与窄屏抽屉。
- 确定性单元：只有新增的版本有效性、上下文边界或状态转换规则需要单独测试，不重复测试简单字段透传。
- 模型质量：使用合成的多章故事样本，包含伤势变化、倒叙、同名角色、未揭示秘密和已修改前文；人工检查证据是否支持结论，不能只用固定模型措辞断言正确性。
- 复用现有 AI 候选显式应用、过期版本拒绝、作品权限、编辑器保存失败与草稿保护测试模式。首期不要求外部真实模型参与每次自动化测试。

本轮仅核对现有测试覆盖位置，未新增代码、未执行这些拟议验收。

## 9. 尚需确认的设计分支

| 决策           | 建议答案                                               | 原因                                         |
| -------------- | ------------------------------------------------------ | -------------------------------------------- |
| 回顾的剧情范围 | 默认只含当前章节之前的信息；作者可明确切换查看后续计划 | 避免把计划当事实、把未来状态带入当前章       |
| 首次建立摘要   | 单章手工填写或显式生成，已有摘要复用；批量初始化后置   | 首次可用门槛低，避免无提示的大量调用与成本   |
| 首期事实粒度   | 人物简短状态 + 来源章节 + 作者确认，复杂状态推演后置   | 避免作者为了使用回顾先填写大量资料           |
| 回顾入口       | 复用现有右侧上下文面板，设为页签，不默认占满写作空间   | 符合现有工作台结构，窄屏仍有明确返回路径     |
| 验收入口       | 采用第 8 节的一条主要作者流程，API 补权限与版本边界    | 高层验证直接体现价值，底层覆盖不可绕过的约束 |

上述建议仍需在可实施规格中确认；主 PRD 与需求池任务已建立，但不将推荐答案当成用户已批准的默认值。
