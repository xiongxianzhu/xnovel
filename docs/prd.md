## 1. 项目概述

### 1.1. 背景与目标

#### 1.1.1. 产品背景

xnovel 是面向小说创作者的开源创作工作室。它帮助作者从灵感和结构规划进入正文写作，并在同一作品空间管理人物、世界设定和 AI 辅助记录。

产品同时支持短篇、中篇和长篇。作品结构不强制等同于“卷—章”，短篇可以直接使用单文档完成创作。

#### 1.1.2. 目标用户

首版服务独立小说作者，包括类型小说、网文和传统叙事创作者。用户需要一个比通用笔记更懂故事结构、又比全自动生成工具更尊重作者控制权的工作空间。

下一阶段优先服务长篇连载作者，重点减少隔天续写时的剧情遗忘、人物与设定前后矛盾，以及未完成线索和存稿安排不清造成的断更。新增能力先在 Web 落地，Desktop 在业务规则验证后补齐，不改变短篇和中篇的基础创作流程。

#### 1.1.3. 核心目标

| ID   | 目标                        | 首版衡量方式                             |
| ---- | --------------------------- | ---------------------------------------- |
| G-01 | 降低从灵感到正文的切换成本  | 新作品可以在同一工作区完成规划与写作     |
| G-02 | 减少设定分散和前后矛盾      | 人物、世界设定和正文可关联查看           |
| G-03 | 提供可控的 AI 辅助          | 用户明确触发任务，并在写入正文前确认结果 |
| G-04 | 支持不同篇幅                | 单文档短篇和多文档长篇使用同一作品模型   |
| G-05 | 支持无需登录的桌面创作      | 无网络时可以保存并重新打开本地作品       |
| G-06 | 提供一致的个性化体验        | Web 提供三语言，两端共用主题语义契约     |
| G-07 | 支持安全、可控的 Skill 扩展 | 用户明确启用并为具体 AI 任务选择 Skill   |

长篇连载增量目标（尚未验收）：

| ID   | 目标                   | 增量衡量方式                                                                           |
| ---- | ---------------------- | -------------------------------------------------------------------------------------- |
| G-08 | 降低继续写作的恢复成本 | 作者能在回顾中找到前情、相关人物状态与未完成线索；通过自愿试用比较开稿到继续写作的用时 |
| G-09 | 提高跨章资料的可核对性 | 摘要与事实可查看来源；前文修改后能识别过期资料；一致性疑点提供原文证据                 |
| G-10 | 支持稳定连载与修订交付 | 作者能区分待写、待修与可交付稿件，查看未处理事项，并按自己设定的更新安排估算存稿余量   |

用时、误报率与模型成本的量化目标需先建立试用基线；不得将模型生成量或功能打开次数直接当作创作质量指标。

### 1.2. 范围边界

#### 1.2.1. 范围内

- 当前范围覆盖作品与文档管理、正文写作、规划设定、可控 AI 辅助、导出、Web 账户和管理，以及无需登录的 Desktop 创作。
- 长篇连载增量 FR-012～FR-029 已在 Web 实现；Desktop 本轮补齐 FR-018 的历史浏览、比较和恢复，其余长篇功能后续独立实施。
- 需求、验收与分期分别见第 2 节和第 5.1 节；文档入库不等于功能已交付。

#### 1.2.2. 范围外（暂不进入首版）

- 作品发布、付费订阅和读者社区。
- 多人实时协同编辑。
- 移动端原生应用。
- 无需作者确认的全自动成书或自动发布。
- Skill 市场、跨用户共享、Web 与 Desktop Skill 同步和 Skill 代码执行。
- Desktop 账户登录、运行时 Logo 配置或修改本地 Skill 文件。

#### 2.1.2. P1 能力与延续范围

- 版本历史与段落级回溯：完整版本检查点、比较与恢复见 FR-018；段落级回溯后置。Web 和 Desktop 均支持历史浏览、命名检查点、完整版本比较与恢复；自动快照保留 90 天，命名检查点不自动清理。
- 一致性检查、伏笔追踪和人物关系视图：一致性与伏笔的可操作闭环见 FR-020～FR-024；通用 AI 任务类型不代表这些功能已经完成，人物关系可视化继续后置。
- 无需登录的桌面端、本地 SQLite 持久化与本地文件集成。
- 桌面端自动更新、数据库迁移和升级前备份。
- 更多导出格式与排版模板。
- Web 支持简体中文、繁体中文和英文切换。
- Web 与 Desktop 共用五套主题家族，并支持浅色、深色和跟随系统。
- Web 用户上传和管理私有 Skill；Desktop 只读识别 `~/.agents/skills/` 下的本地 Skill。

### 2.2. 详细需求

各需求沿用既有描述和验收条件；FR-012～FR-029 的实现范围为 Web；其中 FR-018 同时覆盖 Desktop。

#### 2.2.1. 作品（FR-001）

- **需求描述**：创建、重命名、归档、删除和打开作品
- **验收标准**：用户可以恢复最近打开的作品；Desktop 删除作品为彻底删除，需在应用内二次确认

#### 2.2.2. 结构（FR-002）

- **需求描述**：管理作品大纲、可排序文档树与节点删除
- **验收标准**：大纲作为可编辑文档；每个作品至少保留一个当前正文，归档与删除两条路径均强制；删除文件夹递归删除子树

#### 2.2.3. 写作（FR-003）

- **需求描述**：编辑正文并持续保存草稿
- **验收标准**：刷新页面后已保存内容不会丢失

#### 2.2.4. 设定（FR-004）

- **需求描述**：管理人物和世界设定
- **验收标准**：正文可显式引用同作品人物和世界设定

#### 2.2.5. AI（FR-005）

- **需求描述**：配置 Provider 并发起辅助任务
- **验收标准**：支持内置目录和自定义模型，密钥不进入浏览器或正文日志

#### 2.2.6. 导出（FR-006）

- **需求描述**：导出作品正文
- **验收标准**：支持 Markdown 与纯文本，默认 Markdown

#### 2.2.7. 账户（FR-007）

- **需求描述**：Web 本地账号注册、登录和会话
- **验收标准**：用户名必填；邮箱和手机号可选；支持三种标识登录

#### 2.2.8. 资料（FR-008）

- **需求描述**：管理个人资料和头像
- **验收标准**：可编辑唯一用户名、昵称、唯一邮箱、唯一手机号、现住址和两类头像来源；私密字段不进入管理员列表

#### 2.2.9. 管理（FR-009）

- **需求描述**：初始化管理员并强制首次改密
- **验收标准**：CLI 创建默认管理员；首次登录必须设置新密码

#### 2.2.10. 控制台（FR-010）

- **需求描述**：提供角色感知的 Web 控制台导航
- **验收标准**：普通用户与管理员看到符合权限的菜单和页面入口

#### 2.2.11. 写作安全（FR-011）

- **需求描述**：跨端保护未保存正文与 AI 应用边界
- **验收标准**：保存竞态、切换、崩溃草稿和过期候选均不能静默覆盖正文

#### 2.2.12. 写前回顾（FR-012）

- **需求描述**：在当前作品中汇总前情、相关人物状态和未完成线索
- **验收标准**：三类内容有明确区域与空状态；每条资料可查看来源或人工记录标识；打开回顾不自动调用模型，不覆盖正文，关闭后可继续写作

#### 2.2.13. 章节摘要（FR-013）

- **需求描述**：手工填写或显式生成可审核的章节摘要
- **验收标准**：摘要关联作品、来源章节和正文版本；AI 输出先成为候选，作者可修改、确认或丢弃；来源变化后标为过期，生成或更新失败保留已有资料

#### 2.2.14. 事实与人物状态（FR-014）

- **需求描述**：保存作者确认的人物状态和事实记录
- **验收标准**：首批支持简短状态、来源章节及剧情适用位置；区分作者确认事实、AI 推断与创作计划；冲突记录不得静默覆盖，不把未来状态默认用于当前章

#### 2.2.15. 未完成线索（FR-015）

- **需求描述**：快速记录未处理事项和下次写作接续点
- **验收标准**：支持标题、说明、关联章节及待处理、已处理、暂不处理状态；添加或查看不丢失正文草稿；状态由作者决定，AI 不自动认定完成

#### 2.2.16. AI 上下文（FR-016）

- **需求描述**：提供回顾任务的输入清单与预算反馈
- **验收标准**：生成前显示选定章节、摘要、人物/设定和 Skill；用量估算与供应商实际值分开；来源无权限、失效或预算不足时明确处理，不静默截断或默认发送完整作品

首批人物状态采用轻量记录，不要求作者先整理完整知识库；未完成线索先支持手工管理，完整伏笔生命周期属于 FR-020。回顾必须在没有 AI 服务时仍能读取和编辑已保存资料。

#### 2.2.17. 全文检索（FR-017）

- **需求描述**：搜索当前作品的正文、大纲、人物和设定
- **验收标准**：按关键词展示命中上下文和所在章节/条目，可跳转定位；支持人名或已记录别名查找；默认排除归档内容，需显式纳入；首期不做跨章批量替换

#### 2.2.18. 版本历史（FR-018）

- **需求描述**：命名检查点、完整版本差异比较与恢复
- **验收标准**：Web 增加正文历史，Desktop 复用已有快照；恢复产生新版本并保留恢复前正文；未保存草稿或并发修改不得静默覆盖，自动快照保留 90 天，命名检查点不自动清理

#### 2.2.19. 稿件导入（FR-019）

- **需求描述**：导入 TXT/Markdown 并预览章节拆分
- **验收标准**：写入前预览编码、章节标题和顺序，允许手动纠正拆章；重复标题提供处理选项；确认前不写入，失败不得留下无法解释的半部作品

#### 2.2.20. 伏笔（FR-020）

- **需求描述**：跟踪埋设、推进、回收和放弃
- **验收标准**：记录来源章节与可选目标章节；来源失效时提示；超出目标章节仅提醒，允许作者有意保留或放弃，不自动判错或认定回收

#### 2.2.21. 时间线（FR-021）

- **需求描述**：管理故事事件与叙述位置
- **验收标准**：事件可关联人物、地点、来源和相对顺序，允许未知时间；区分发生顺序与叙述顺序，倒叙不自动判为矛盾，不强迫使用公历

#### 2.2.22. 知情范围（FR-022）

- **需求描述**：记录角色获得信息与秘密揭示的阶段
- **验收标准**：区分作者、读者及人物已知信息；检查只提出有出处的疑点；谎言、伪装和不可靠叙述允许作者标为有意安排

#### 2.2.23. 一致性检查（FR-023）

- **需求描述**：对指定章节范围生成可处理的问题清单
- **验收标准**：每项提供问题类型、双方原文出处和理由；无证据推测单独标记；支持待处理、已解决及忽略并记录理由，不自动修改正文

#### 2.2.24. 修改影响（FR-024）

- **需求描述**：修改设定后检查可能受影响的正文与资料
- **验收标准**：列出显式引用和检索命中的影响候选，允许回看原文并逐项处理；不得宣称穷尽所有影响，不执行全书自动替换

FR-021～FR-024 依赖可核对的来源、人物状态与剧情范围；一致性检查的验收不能只看模型是否返回一段分析文字。

#### 2.2.25. 章节规划（FR-025）

- **需求描述**：以卡片记录章节目标和故事线
- **验收标准**：可选填视角、目标、冲突、转折和结尾悬念；不强制套用模板；调整卡片是否改变正文顺序必须明确；规划不得当成已发生事实

#### 2.2.26. 连载管理（FR-026）

- **需求描述**：维护更新安排、稿件状态和存稿余量
- **验收标准**：区分草稿、待修、可交付和作者手动标记的已发布；仅以未发布的可交付稿件计算存稿；未设置安排时显示未设置，不伪装连接发布平台

#### 2.2.27. 修订支持（FR-027）

- **需求描述**：管理正文修订待办与作品文风约定
- **验收标准**：待办可关联正文位置，来源失效时提示；支持术语、视角、时态和表达约定；检查项逐条接受或忽略，文风评价明确为建议，不提供虚构爆款评分

#### 2.2.28. AI 历史（FR-028）

- **需求描述**：查询和找回历史任务及候选
- **验收标准**：按作品、章节、类型、时间和状态筛选；历史候选可阅读和复制，应用仍校验目标与版本；重试由作者触发，供应商未返回的用量显示未知

#### 2.2.29. 交稿导出（FR-029）

- **需求描述**：导出前预检和配置正文输出
- **验收标准**：预览章节范围、顺序、标题和分隔方式；提示空章、重复标题、占位内容与待办；不自动删除内容，不将私有设定或回顾资料混入正文，导出不等于发布

FR-028 承接现有 T-413 的 AI 任务与结果查询部分，并补充候选找回及应用保护；不替代该任务中登录会话和 Skill 版本查询的范围。

### 2.3. 核心用户流程

#### 2.3.1. 当前创作流程

1. 用户创建作品并选择短篇或自定义结构。
   作品维护封面、名称、作者署名、简介、书号、创作进度、管理状态和时间；章节数与字数由当前正文自动汇总。作者署名可留空、最多 100 个字符，独立于账号昵称。作品列表仅按书名或作者名搜索，可叠加未开始、连载中、已完结筛选，并保留搜索与分页 URL 条件。
   “查看详情”进入独立资料页，展示完整作品属性；“进入写作”保持原工作区入口。创建和编辑表单可维护作者署名，旧作品作者默认留空，不自动推断。
2. 用户记录灵感、梗概、人物和世界设定。
3. 用户建立大纲或直接进入正文。
   文档树允许建立文件夹和正文、调整层级与顺序、归档和恢复节点，但不能归档或删除作品的最后一个当前正文。
   删除是彻底删除，不可恢复，Desktop 需在应用内确认对话框中显式确认；删除文件夹会连同子树内的已归档节点一起删除。
   大纲作为纯文本大纲文档保存；正文可以显式关联人物与世界设定，关联不会自动修改正文。
4. 用户写作并按需调用 AI 辅助任务。
5. 用户确认、修改或拒绝 AI 结果。
6. 用户默认导出 Markdown，也可以选择纯文本，或继续维护作品。

Web 首次访问时，用户可以使用用户名、已填写的邮箱或已填写的手机号登录。邮箱和手机号首版不要求验证。公开注册由管理员通过数据库中的站点设置动态开启或关闭，默认关闭。Desktop 不进入登录流程。

首个管理员通过 API CLI 初始化，默认用户名为 `admin`，昵称为“管理员”，邮箱和手机号为空。初始化密码为一次性引导密码 `123456`；管理员首次登录后必须先设置新密码，完成前不能访问作品、偏好和其他业务工作区。

登录后的 Web 控制台提供仪表盘、作品、AI 模型、Skills 和系统设置入口。Web 全局输入框最多使用 1px 细边框，聚焦不叠加粗外框，下拉菜单项的悬停与选中背景使用直角。偏好设置通过布局缩略卡片展示现有五套主题，顶部外观菜单通过双列色卡快速切换，显示模式与账号偏好保存保持不变。顶部外观入口仅显示图标，语言入口显示图标和“中／繁／EN”缩写，完整菜单仍提供三种语言和全部外观选项。管理员额外可以管理用户，并查看登录日志和操作日志。Web 所有数据记录列表（模型、Skills、作品管理及创作资料；仪表盘保留封面书架）统一使用字段独立分列的表格和仅图标的行操作，用途通过悬停/聚焦说明；所有下拉选择使用共享主题化控件并即时开合，保留必填校验与禁用保护。模型连接的搜索框在桌面为紧凑宽度并与表格分隔，列表及创建、编辑页统一称“提供商ID”。用户管理与登录日志同样使用细边框筛选和上述表格规范，保留服务端筛选、分页和独立详情，窄屏仅表格局部横向滚动。用户管理支持创建、查询、编辑、停用与恢复；停用采用软删除语义并立即撤销有效会话，不删除作品或审计历史。登录日志来自登录会话历史，操作日志来自不可变管理员审计事件，两类日志均为只读。尚未实现的其他模块显示占位状态，不展示虚构数据或操作。

管理员可在“系统设置”配置站点名称与 Logo：名称去除首尾空白后为 1–100 个字符，默认 `xnovel`；Logo 选择后先预览，再明确保存，并支持确认移除。名称与 Logo 分别保存并提供成功、失败反馈，失败保留输入。公开配置用于顶部导航、登录页与浏览器标题；未配置 Logo 或图片失败时显示名称。普通用户只能读取品牌，系统设置入口仍提供个人偏好，不能修改全站配置。

右上角账户菜单提供个人资料、修改密码、偏好设置和退出登录。个人资料页支持编辑唯一用户名、昵称、唯一邮箱、唯一 E.164 手机号和现住址；修改用户名、邮箱或手机号必须再次确认当前密码。头像通过“本地图片”和“在线图片”选项卡选择来源：本地支持 10 MiB 以内的 PNG、JPEG、WebP，在线图片必须通过 HTTPS 地址安全校验；当前头像可以点击打开预览。

Web 侧栏仅提供一个“Skills”入口，不单列“Skill 安全”；普通用户管理自己的私有 Skills，管理员在同一页面切换“个人 Skills / 安全管理”，继续提供元数据查看、隔离和解除隔离。安全管理保持管理员权限，旧 `/admin/skills` 地址经权限校验后跳转到 `/skills?tab=security`。

需要 Skill 时，Web 用户从自己的私有 Skill 列表选择已启用版本；Desktop 用户从本机一级 Skill 目录中查看并启用。两端都只把明确选择的 Skill 作为不可信 AI 上下文，不执行其中的脚本、二进制或安装命令。

Web 与 Desktop 均保持纯文本正文模型，提供查找、替换、总字数、选区字数、自动保存和 `Ctrl/Cmd+S`。Desktop 作品内使用文件夹、正文和大纲组成单一文档树；未保存正文写入独立本地草稿，切换作品或文档时由作者选择保存、保留草稿或留在当前正文。AI 候选绑定生成时文档与正文版本；正文或草稿变化后不能直接应用过期候选。

Web 写作页以正文为主体：编辑器填满侧栏与可见上下文面板之外的可用宽度，并扩展到剩余视口高度；正文行宽通过内部留白控制。侧栏保留作品名、作者与字数摘要，完整简介和书号在独立作品资料页查看。窄屏操作按可用空间换行，保存、查找和上下文面板仍可操作。

Web 写作工作台将作品摘要集中在章节侧栏，顶部面包屑提供作品列表与资料入口；正文顶部仅保留章节标题和工具栏，保存状态与字数位于底部。默认收起 AI 面板。专注模式隐藏左右面板并保留退出、保存入口，切换不丢失草稿或候选，也不改变已保存的侧栏偏好。

Web 支持选中已保存正文后发起润色、扩写或精简：动作先填入 AI 面板，不自动调用模型。用户确认生成后得到独立候选；再次确认才替换原选区，其他正文保留。原文档或版本不匹配时拒绝应用，运行中的任务和未处理候选不会被新的选区动作覆盖。

Web 仪表盘采用书架布局，展示按更新时间倒序的最多四部当前作品，以及最新作品的继续写作入口；提供创建作品、全部作品、AI 模型和私有 Skills 入口。没有作品时提供创建引导，封面缺失或加载失败时展示书名与作者，不生成虚构作品和统计。

登录后的全局导航右上角提供外观与语言快捷切换，复用现有账号偏好：五套配色、浅色/深色/跟随系统，以及简体中文/繁體中文/English。选择后立即生效并保存，刷新后恢复；保存期间防止重复并发切换，失败显示反馈。移动端保留有可访问名称的图标入口。

#### 2.3.2. 写前回顾流程（Web）

1. 作者打开作品中的当前章节，进入写前回顾，查看前情、相关人物状态和未完成线索。
2. 已有资料直接读取。资料不足时，作者可以手工填写，或选择来源并显式请求 AI 生成摘要候选；不能因打开页面自动发起模型调用。
3. 作者查看来源章节及版本，修改、确认或丢弃候选；未确认内容不进入正式事实记录。
4. 回顾按明确的剧情范围展示资料，将已确认、待确认、过期和计划分别标识。默认查看当前章之前的资料，后续计划在独立资料类别中管理，不得将未来计划混同于已发生事实。
5. 作者点击来源核对原文；跳转和返回沿用现有未保存草稿保护。旧段落无法可靠定位时提示来源变化，提供打开来源章节的路径。
6. 作者继续写作，随时记录下次接续点。来源正文、章节顺序或相关设定发生变化时，重新判断摘要及状态记录的有效性；失效资料不得继续显示为当前事实。

例如，作者修改第 12 章中的受伤情节后，第 13 章回顾中引用该来源的旧伤势记录必须提示过期；更新失败应保留旧记录及过期标识，不能将失败结果当作更新成功。

回顾入口在后续 Web 设计中确定，优先评估复用现有上下文面板。具体交互获批时，必须同步 `apps/web/DESIGN.md` 的面板、来源状态、窄屏和焦点规则。

## 3. 非功能需求

### 3.1. 性能

**当前约束**

- Web 每用户最多同时运行两个 AI 调用，单次最长 120 秒，平台输出硬上限为 8,192 tokens；首版不设置日/月配额。

**长篇增量约束**

- 参考规模为单部 1000 章、300 万汉字；服务端普通列表/回顾 P95 ≤1 秒，全文检索 P95 ≤2 秒。本地实测与环境见验收记录，模型效果与浏览器网络耗时另行评估。

### 3.2. 安全

**当前约束**

- 浏览器端不保存模型供应商的长期密钥。
- Web 用户使用自己的 Provider 密钥；密钥在服务端加密保存，内置地址覆盖和自定义地址受部署级允许列表约束。
- 桌面端 renderer 不直接访问 SQLite、任意文件路径或 AI 密钥。
- 桌面端 AI 密钥由主进程使用操作系统支持的密码学能力加密，应用只持久化密文，不以明文写入 SQLite。
- 日志不记录完整正文、模型密钥或未经处理的敏感输入。
- Web 直接保存规范化后的用户名、可选邮箱和可选 E.164 手机号；非空邮箱和手机号分别保持唯一。邮箱和手机号首版不要求验证，也不用于找回密码。用户展示名称使用可重复的昵称。
- 正式新密码长度为 `8`–`32` 位，至少满足大写、小写、数字、特殊字符四类中的两类；不得使用 `123456`、`password`、用户名或邮箱本地部分。管理员一次性引导密码 `123456` 是唯一例外。
- Web Skill 包不超过 10 MiB，解压后不超过 50 MiB 和 500 个文件；归档路径必须先完成碰撞与越界校验。
- Desktop Skill 在启用和每次 AI 任务前校验内容指纹及资源上限，原目录保持只读。

**长篇增量约束**

- 回顾、摘要、事实和线索均属于作者作品数据；API 必须验证作品所有权和同作品来源关系，不能只依赖前端筛选。
- 完整上下文只在作者有权限的业务流程中使用，不进入日志或审计快照；估算 Token 与实际 Token 区分，缺失用量不填零冒充真实值。

### 3.3. 兼容性与可访问性

**当前约束**

- 桌面端不要求账户登录，基础写作和保存不依赖网络或 FastAPI。
- 核心写作流程支持键盘操作和清晰焦点状态。
- 用户头像上传不超过 10 MiB，Web 全局 Logo 上传不超过 5 MiB；Desktop Logo 在构建时固定。

**长篇增量约束**

- 新界面覆盖三种语言、键盘操作、清晰焦点、加载、空、错误、过期和窄屏状态；不得靠颜色独自表达确认或失效。

### 3.4. 可靠性与内容保护

**当前约束**

- 正文编辑不依赖 AI 服务可用性。
- AI 请求失败不能覆盖原文或未保存草稿。
- 保存期间产生的新输入必须继续保持未保存状态并进入下一次保存，旧响应不得误报完成。
- 本地草稿、正式正文和 AI 候选是三个独立状态，任何一方都不得未经作者确认覆盖另一方。

**长篇增量约束**

- 来源版本有效性和候选确认规则在可信服务端执行；生成期间来源变化后，旧候选可保留查看，但不能直接确认成最新资料。
- 人工事实、AI 推断、创作计划和正式正文保持独立状态；资料修改时间不等于事件发生时间，叙述顺序不等于故事时间。
- 来源归档、删除、失去访问权或章节重新排序后，应重新校验显示范围与引用有效性；不能跳到无关段落或静默使用失效内容。
- 已保存的回顾资料在 AI 不可用时仍可读取和编辑；生成超时、取消、部分输出或预算超限不得破坏正文和已确认资料。

## 4. 数据与接口

### 4.1. 数据模型

#### 4.1.1. 现有业务数据

| 数据领域         | 业务内容与边界                                                                           |
| ---------------- | ---------------------------------------------------------------------------------------- |
| 作品与文档       | 作品属性、文档树、正文、文档版本与未保存草稿；正文版本号不等于历史版本浏览能力           |
| 人物与世界设定   | 同作品内的资料及正文显式引用；不将关联操作当作正文修改                                   |
| Web 账户与配置   | 用户资料、会话、角色、偏好及全站品牌配置；管理员查询遵循脱敏与授权边界                   |
| AI 与 Skill      | Provider 配置、加密凭据、任务、候选与 Skill 元数据；候选和正式正文分离，Skill 内容不执行 |
| Desktop 本地数据 | 本地 SQLite、正文快照、草稿及备份；与 Web 独立持久化，不隐式同步                         |

具体表、字段、关联和迁移以 [数据库文档](database.md)、模型与迁移为准；服务归属见 [架构文档](architecture.md)。

#### 4.1.2. 长篇增量数据

- 摘要、事实、线索、事件、知情记录、问题、章节计划、修订待办和文风约定分别持久化；都包含非空时间戳与中文模型、迁移注释。
- 资料保存来源章节、正文版本与来源之前的叙述顺序指纹。来源修改、归档、删除或前缀重排后标为失效；追加未来章节不会使既有资料失效。
- 故事事件顺序 `story_order` 与文档树叙述顺序分离；未知时间保留为空，不自动推断。事实、推断与计划分别标注；多个状态保留并列，由作者判断。
- 批次、逐章项目、导入幂等回执和正文历史独立保存。普通 AI 历史保留 30 天，收藏候选和已确认结果不自动清理；已确认业务资料、审计及有效 Skill 版本不纳入到期清理。

### 4.2. 接口要求

**当前约束**

- 服务端 API 使用版本前缀，并为未来可选同步保留演进空间。

| 调用边界                  | 现有要求与专项来源                                                                                        |
| ------------------------- | --------------------------------------------------------------------------------------------------------- |
| Web → FastAPI             | 业务操作由 API 校验身份、权限与作品范围；请求字段、路径和错误契约见 [API 文档](api.md)                    |
| Desktop renderer → 主进程 | 通过受限 preload IPC 访问本地能力，renderer 不直接访问 SQLite、文件或密钥；见 [架构文档](architecture.md) |
| AI 辅助调用               | Web 由 FastAPI、Desktop 由主进程调用 Provider，结果先成为候选；见 [AI 接入文档](ai-integration.md)        |
| 长篇增量接口              | 摘要、来源校验、线索等接口已经实现；沿用作品权限、页码分页与版本保护，完整契约见 API 文档与 OpenAPI       |

## 5. 约束与假设

### 5.1. 技术与交付约束

- 本轮覆盖 T-411～T-413、T-601～T-618；Web 实现全部，Desktop 仅补齐历史功能。
- 右侧回顾、AI 与规划面板同一时间只展开一个；大型列表、创建、编辑和详情使用独立页面。导航、后退和来源跳转统一保护未保存正文及持久化资料表单。
- 手工摘要和显式逐章/批量摘要并存；AI 摘要先成为候选，确认后才能进入前情。分析结果不能通过正文应用接口写入正式稿件。
- 批量任务由单个 API 进程后台执行，关闭浏览器不停止任务。每用户串行执行一个批量子任务，并共享现有两调用并发上限。
- 服务重启把中断批次标为暂停，运行项目标为失败；作者选择继续未开始项或重试失败项，成功项目不再派发。取消停止后续派发，当前已发起调用可能已经计费。
- 生成前显示输入范围、来源和保守中文 Token 估算；成本未知时直接标为未知。超长章节显式分段，必要时合并摘要；不截断正文来绕过预算。
- 一致性检查读取当前所选章，可选择同一范围内前两章作为参考，结构化疑点必须包含可在两处来源中找到的原文证据；不是全书任意两章的穷尽检查，也不保证模型发现全部冲突。
- 全文检索使用 PostgreSQL 项目范围过滤和 `pg_trgm`；默认排除归档。来源跳转打开章节查找，资料名称命中进入独立详情。
- 导入支持 UTF-8/BOM、UTF-16 与 GB18030，20 MiB、最多 1000 章；可修正拆章、合并、排序，默认保留同名章节而不覆盖，确认后原子提交。
- 章节计划顺序不改变正文树顺序；存稿按每章最新交付记录去重，只有非空、来源有效、未发布的可交付正文计入。未设置更新频率时不估算天数；发布状态由作者记录。
- 术语检查采用逐字匹配，视角、时态和表达约定供人工核对；检查结果可显式转为修订待办。导出预检识别空章、重复标题、待补和未处理修订，输出只含所选正文。

### 5.2. 已确认假设与选择

Web 仍使用本地账号与可撤销会话，公开注册默认关闭；Desktop 无登录、无 FastAPI sidecar，不隐式同步数据。管理员用户删除保持停用语义；登录会话详情只对管理员开放，Skill 版本全文只对所有者开放。

自动正文历史保留 90 天，命名检查点长期保留；普通 AI 历史保留 30 天，收藏及已确认结果除外。恢复之前保存当前正文，恢复产生新版本且校验并发；相同正文的普通保存不新增快照。完整版本比较超出计算预算时使用原文并排回退。

PRD 影响：是。已更新 FR-012～FR-029、2.3 流程、2.4 验收范围、3.1 性能、4.1 数据及第 5 节的后台、保留和交付约束。

Web DESIGN.md 影响：是。已同步独立页面、右侧回顾、来源状态、批量进度、历史比较与移动端契约。

### 5.3. 后续事项

跨端云同步、Desktop 其余长篇能力、自动人物关系图、复杂历法、段落级恢复、自动发布和全书穷尽分析不在本轮。真实用户自愿试用及模型质量评估需要另行收集反馈；本地合成测试不能代替这些结论。

## 6. 附录

### 6.1. 术语表

| 术语       | 含义                                                                 |
| ---------- | -------------------------------------------------------------------- |
| 作品       | 管理一部小说及其文档、人物、设定和辅助资料的创作空间                 |
| 文档       | 文档树中的正文或大纲等内容单元；作品结构不强制等同于卷章             |
| 正式正文   | 作者已保存的当前正文，与未保存草稿及 AI 候选分别管理                 |
| AI 候选    | 尚待作者决定是否接受的模型输出，不能未经确认覆盖正文或结构化设定     |
| 写前回顾   | 已实现的前情、人物状态和未完成线索汇总，用于帮助作者继续写作         |
| 来源版本   | 摘要、候选或事实记录所依据的正文版本，用于识别过期内容               |
| 创作计划   | 作者设想的后续安排，不等同于正文中已经发生的事实                     |
| 剧情范围   | 回顾或辅助任务适用的故事信息边界，不能把未来计划默认带入当前章       |
| Skill      | 作者明确选择的不可信 AI 上下文材料，任何端均不得执行其脚本或安装命令 |
| FR / G / T | 分别为功能需求、产品目标和实施任务编号，用于关联需求与验收           |
