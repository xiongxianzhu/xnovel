# xnovel 产品需求文档

> 文档状态：Draft  
> 文档版本：0.1.0  
> 最后更新：2026-08-16

## 1. 产品概述

xnovel 是面向小说创作者的开源创作工作室。它帮助作者从灵感和结构规划进入正文写作，并在同一作品空间管理人物、世界设定和 AI 辅助记录。

产品同时支持短篇、中篇和长篇。作品结构不强制等同于“卷—章”，短篇可以直接使用单文档完成创作。

## 2. 目标用户

首版服务独立小说作者，包括类型小说、网文和传统叙事创作者。用户需要一个比通用笔记更懂故事结构、又比全自动生成工具更尊重作者控制权的工作空间。

## 3. 产品目标

| ID   | 目标                        | 首版衡量方式                             |
| ---- | --------------------------- | ---------------------------------------- |
| G-01 | 降低从灵感到正文的切换成本  | 新作品可以在同一工作区完成规划与写作     |
| G-02 | 减少设定分散和前后矛盾      | 人物、世界设定和正文可关联查看           |
| G-03 | 提供可控的 AI 辅助          | 用户明确触发任务，并在写入正文前确认结果 |
| G-04 | 支持不同篇幅                | 单文档短篇和多文档长篇使用同一作品模型   |
| G-05 | 支持无需登录的桌面创作      | 无网络时可以保存并重新打开本地作品       |
| G-06 | 提供一致的个性化体验        | Web 提供三语言，两端共用主题语义契约     |
| G-07 | 支持安全、可控的 Skill 扩展 | 用户明确启用并为具体 AI 任务选择 Skill   |

## 4. 首版范围

### 4.1 P0 能力

| ID     | 模块 | 需求                         | 验收标准                                             |
| ------ | ---- | ---------------------------- | ---------------------------------------------------- |
| FR-001 | 作品 | 创建、重命名、归档和打开作品 | 用户可以恢复最近打开的作品                           |
| FR-002 | 结构 | 管理作品大纲和可排序文档树   | 短篇允许只有一个正文文档                             |
| FR-003 | 写作 | 编辑正文并持续保存草稿       | 刷新页面后已保存内容不会丢失                         |
| FR-004 | 设定 | 管理人物和世界设定           | 设定可以按作品查询和编辑                             |
| FR-005 | AI   | 配置 Provider 并发起辅助任务 | 支持内置目录和自定义模型，密钥不进入浏览器或正文日志 |
| FR-006 | 导出 | 导出作品正文                 | 首版至少支持 Markdown 或纯文本                       |
| FR-007 | 账户 | Web 本地账号注册、登录和会话 | 支持用户名、邮箱或手机号登录                         |
| FR-008 | 资料 | 管理个人资料和头像           | 私密字段不会出现在管理员列表                         |

### 4.2 P1 能力

- 版本历史与段落级回溯。
- 一致性检查、伏笔追踪和人物关系视图。
- 无需登录的桌面端、本地 SQLite 持久化与本地文件集成。
- 桌面端自动更新、数据库迁移和升级前备份。
- 更多导出格式与排版模板。
- Web 支持简体中文、繁体中文和英文切换。
- Web 与 Desktop 共用五套主题家族，并支持浅色、深色和跟随系统。
- Web 用户上传和管理私有 Skill；Desktop 只读识别 `~/.agents/skills/` 下的本地 Skill。

### 4.3 暂不进入首版

- 作品发布、付费订阅和读者社区。
- 多人实时协同编辑。
- 移动端原生应用。
- 无需作者确认的全自动成书或自动发布。
- Skill 市场、跨用户共享、Web 与 Desktop Skill 同步和 Skill 代码执行。
- Desktop 账户登录、运行时 Logo 配置或修改本地 Skill 文件。

## 5. 核心流程

1. 用户创建作品并选择短篇或自定义结构。
2. 用户记录灵感、梗概、人物和世界设定。
3. 用户建立大纲或直接进入正文。
4. 用户写作并按需调用 AI 辅助任务。
5. 用户确认、修改或拒绝 AI 结果。
6. 用户导出正文或继续维护作品。

Web 首次访问时，用户先使用用户名、已验证邮箱或已验证手机号登录。公开注册由管理员通过数据库中的站点设置动态开启或关闭，默认关闭。Desktop 不进入登录流程。

需要 Skill 时，Web 用户从自己的私有 Skill 列表选择已启用版本；Desktop 用户从本机一级 Skill 目录中查看并启用。两端都只把明确选择的 Skill 作为不可信 AI 上下文，不执行其中的脚本、二进制或安装命令。

## 6. 非功能要求

- 正文编辑不依赖 AI 服务可用性。
- AI 请求失败不能覆盖原文或未保存草稿。
- 浏览器端不保存模型供应商的长期密钥。
- Web 用户使用自己的 Provider 密钥；密钥在服务端加密保存，内置地址覆盖和自定义地址受部署级允许列表约束。
- Web 每用户最多同时运行两个 AI 调用，单次最长 120 秒，平台输出硬上限为 8,192 tokens；首版不设置日/月配额。
- 桌面端不要求账户登录，基础写作和保存不依赖网络或 FastAPI。
- 桌面端 renderer 不直接访问 SQLite、任意文件路径或 AI 密钥。
- 桌面端 AI 密钥由主进程使用操作系统支持的密码学能力加密，应用只持久化密文，不以明文写入 SQLite。
- 核心写作流程支持键盘操作和清晰焦点状态。
- 服务端 API 使用版本前缀，并为未来可选同步保留演进空间。
- 日志不记录完整正文、模型密钥或未经处理的敏感输入。
- Web 直接保存规范化后的用户名和邮箱，并与 E.164 手机号分别保持唯一；邮箱和手机号验证后才能用于登录或找回密码。用户展示名称使用可重复的昵称。
- 头像与 Web 全局 Logo 上传均不超过 5 MiB；Desktop Logo 在构建时固定。
- Web Skill 包不超过 10 MiB，解压后不超过 50 MiB 和 500 个文件；归档路径必须先完成碰撞与越界校验。
- Desktop Skill 在启用和每次 AI 任务前校验内容指纹及资源上限，原目录保持只读。

## 7. 首版完成标准

- [ ] 用户能完成“创建作品—规划—写作—保存—导出”闭环。
- [ ] 单文档短篇与多文档作品均通过验收。
- [ ] AI 功能关闭或不可用时，基础写作仍然可用。
- [ ] Web 类型检查、静态检查、测试和生产构建通过。
- [ ] FastAPI 测试和健康检查通过。
- [ ] API、AI 和部署文档与实际实现一致。
- [ ] Desktop 无需登录即可完成“创建作品—写作—保存—重新打开”闭环。
- [ ] Desktop 更新不会删除或静默覆盖本地作品。
- [ ] Web 能完成登录、退出、资料与偏好管理；关闭注册后直接调用注册接口也会被拒绝。
- [ ] `zh-CN`、`zh-TW`、`en-US` 以及五套浅色/深色主题在规定的回退路径下工作。
- [ ] Web 能上传、查看、编辑 `SKILL.md`、删除、启用和禁用自己的 Skill，跨用户读取被拒绝。
- [ ] Desktop 只能列出、查看、重新扫描、启用和禁用本地 Skill，renderer 没有修改本地 Skill 的 IPC 能力。

## 8. 后续决策

以下决策不阻塞当前工程骨架，但必须在相关功能实施前确认：正文版本保留周期、默认导出格式，以及未来是否提供 Web 与 Desktop 云同步。

Web 认证已确定为本地账号和服务端可撤销会话；公开注册由 `site_settings.registration_enabled` 动态控制，默认关闭。

Web 首批 AI Provider、自定义模型、用户自带密钥和用量边界已经确定，见 [`ai-integration.md`](ai-integration.md)。
