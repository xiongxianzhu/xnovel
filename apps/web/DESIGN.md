# xnovel Web 设计规范

本文是 xnovel 网页端视觉与交互的事实来源。目标是建立安静、可信、适合长时间创作的扁平化小说工作台，而不是模仿通用管理后台或营销网站。

## 设计判断

xnovel 是面向持续写作、结构整理和 AI 辅助创作的高频产品界面。视觉采用克制、专业、低装饰的扁平化语言，使用原生 CSS 和项目自有组件。

- `DESIGN_VARIANCE: 4`：布局稳定、层级清楚，工作区允许有限的不对称。
- `MOTION_INTENSITY: 3`：只保留反馈和状态切换所需动效。
- `VISUAL_DENSITY: 6`：支持高频操作，但不压缩正文阅读空间。

这些参数用于校准设计方向，不是呈现给用户的产品设置。

## 设计原则

1. **内容优先**：正文、结构和设定永远比工具栏更醒目。
2. **扁平而有层级**：使用纯色、排版、留白和 1px 边框组织内容。
3. **安静但不苍白**：通过文学化排版与棕褐强调色建立辨识度。
4. **AI 保持可辨识**：AI 输出是候选内容，不能伪装成作者正文。
5. **长时间使用友好**：控制对比度、密度和动效，减少视觉疲劳。
6. **状态完整**：加载、空、失败、离线、禁用和处理中状态都属于设计。
7. **作者始终掌控**：AI 建议不能未经确认覆盖正文或结构化设定。

## 通用扁平业务风格

xnovel Web 吸收通用扁平业务应用的结构化风格，但继续使用本文件定义的 xnovel 配色、文学排版和创作语义。

- 视觉密度保持中高密度，支持快速扫描和高频操作，不压缩正文阅读空间。
- 页面使用 `canvas`、`surface` 和浮层三层表面组织层级。
- 文档流内优先使用纯色、1px 边框、排版和间距，不使用常驻重阴影。
- 页面、列表、仪表盘和工作台采用全宽可用布局，不设置无理由的全局居中最大宽度。
- 数据行、列表项、表格和工具栏保持稳定尺寸；悬停、提示和操作数量不能推动相邻内容。
- 面板只用于真实分组或交互边界，不把每一段普通内容包装成独立卡片。
- 默认矩形圆角继续使用 `2px`；参考系统的更大面板圆角不覆盖 xnovel 主题契约。
- 全项目使用一套图标家族，常规图标尺寸为 `16-20px`，图标按钮必须有可访问名称。

## 品牌气质与视觉禁区

关键词：文学、专注、温暖、克制、可靠。

避免：

- 渐变、霓虹紫、外发光、玻璃拟态和拟物纹理。
- 厚重阴影、大圆角、胶囊按钮和悬浮式装饰。
- 所有内容都装进卡片，或用阴影代替清晰的信息结构。
- 游戏化奖励、持续漂浮、弹跳和无意义的 AI 星光图标。
- 营销页式超大标题、虚构精确数据和装饰性状态点。
- 混用多套图标、圆角、字体或色彩体系。

使用规则：

- `canvas` 是应用背景，`surface` 承载编辑区、面板和浮层。
- `ink` 用于标题与正文主色，`text-muted` 只用于辅助信息。

### 主题契约

- 支持 `manuscript-brown`、`pine-green`、`harbor-blue`、`grape-purple` 和 `graphite`，默认使用 `manuscript-brown`。
- 每个主题必须完整提供上表中的浅色与深色令牌；共享主题清单是 Web 与 Desktop 的唯一颜色事实来源，不能各自复制后独立修改。
- 用户偏好中的 `theme_mode` 为 `system`、`light` 或 `dark`。应用把它解析为根节点的 `data-color-scheme="light|dark"`；`system` 不产生第三套令牌。
- 主题切换只改变语义颜色角色，不改变布局、尺寸、间距、圆角和交互行为。
- 主题在应用根节点统一切换，不能让单个页面或区块自行反转主题。
- 明暗主题保持相同的信息层级、品牌识别和 WCAG AA 对比度。
- Web 在 React 挂载前应用本地缓存，登录后以服务端偏好为准；Desktop 在创建主窗口前读取本地偏好。默认跟随系统，并避免首屏闪烁。

## 排版

### 字体与数字

- 界面正文：`Inter, ui-sans-serif, system-ui, sans-serif`。
- 展示标题：`Georgia, "Times New Roman", "Noto Serif SC", serif`。
- 小说编辑器：`"Noto Serif SC", "Source Han Serif SC", Georgia, serif`。
- 代码与计数：`ui-monospace, "SFMono-Regular", Consolas, monospace`。
- 中文界面优先保证系统 UI 的清晰度，品牌字体不得降低正文可读性。
- 字数、日期、时长、版本号、百分比和可比较数字使用 `font-variant-numeric: tabular-nums`。
- 表格、表单和关键状态不使用装饰字体。

### 字号层级

| 层级           | 字号                         | 行高      | 字重      | 用途                   |
| -------------- | ---------------------------- | --------- | --------- | ---------------------- |
| 品牌展示标题   | `clamp(2.5rem, 7vw, 4.5rem)` | `1.05`    | `500`     | 仅欢迎页或品牌介绍     |
| 页面主标题     | `24-28px`                    | `1.2`     | `600-700` | 作品、列表和详情页标题 |
| 移动端主标题   | `20-24px`                    | `1.25`    | `700`     | 移动页面标题           |
| 区块标题       | `16-18px`                    | `1.4`     | `600`     | 面板和详情分区         |
| 界面正文与控件 | `14-16px`                    | `1.5-1.7` | `400-600` | 表单、按钮和列表正文   |
| 编辑器正文     | `18px`                       | `1.9`     | `400`     | 小说正文               |
| 辅助文本       | `12-13px`                    | `1.5`     | `400-600` | 描述、时间和元数据     |
| 表头           | `12px`                       | `1.4`     | `600-700` | 数据表头               |
| 重点数值       | `28-32px`                    | `1.2`     | `600`     | 必要的摘要指标         |

工作台不使用营销页式超大标题。长篇阅读宽度控制在 65-75 个中文字符附近，不通过缩小字号容纳更多工具。

### 文本行为

- 长表格字段和单行列表标题默认省略，悬停与键盘聚焦时可以查看全文。
- 长文本提示不得改变表格行高或推动相邻布局。
- 需要保留格式的正文、提示词、错误详情和日志允许换行，并提供复制能力。
- 空值统一显示 `-`；未知、无权限和加载状态不能伪装为空值。
- 按钮和标签使用明确动作或状态名称，不使用含糊、夸张或责备用户的文案。
- 按钮文字在桌面端保持单行。必要时缩短文案或增加宽度。
- 空值统一使用 `-`；未知、无权限、加载中和无结果不能伪装为空值。
- 表单、表格和操作区的说明文字保持直接，错误文案优先说明原因和恢复方式。

### 业务数据排布

- 表格表头目标高度约 `42px`，使用低对比表面和 `12px` 半粗体文字。
- 列表记录保持固定或稳定高度；长文本默认单行省略，悬停和键盘聚焦时提供全文。
- 字段较多时只允许表格容器横向滚动，页面壳层和主内容不横向滚动。
- 操作列在桌面端靠右并保持不透明表面；移动端使用更多菜单或操作抽屉。
- 数量、日期、时长、版本、百分比和可比较数字使用 `font-variant-numeric: tabular-nums`。
- 实时筛选默认使用约 `300ms` 防抖，不为无价值的检索再增加提交按钮。
- 异步排序和批量操作使用并发锁；边界按钮禁用，不重复堆叠边界错误。

## 间距、边界与形状

以 4px 为基础单位：

```css
:root {
  --space-1: 4px;
  --space-2: 8px;
  --space-3: 12px;
  --space-4: 16px;
  --space-5: 20px;
  --space-6: 24px;
  --space-8: 32px;
  --space-12: 48px;
  --radius: 2px;
  --border-width: 1px;
  --control-height: 44px;
}
```

- 紧密控件使用 8-12px 间距，页面区块使用 24-48px 间距。
- 面板常规内边距为 20-24px，移动端为 16px。
- 所有矩形按钮、输入框、卡片、面板、菜单、抽屉、模态框、Toast、标签和编辑器表面统一使用 2px 圆角。
- 不建立多级圆角令牌，也不使用胶囊形按钮或标签。
- 单选圆点、开关滑块、头像和状态点等必须表达圆形语义的几何元素可以保持圆形。开关轨道和普通图标按钮仍使用 2px。
- 默认使用 1px 边框。聚焦、悬停和选中不得通过改变边框宽度引发布局抖动。
- 卡片只在表达真实分组或交互边界时使用。普通内容优先通过间距、标题和单条分隔线组织。
- 阴影不是默认层级手段。只有下拉菜单、抽屉和模态框等浮层允许轻微阴影。

## 应用壳层与工作台布局

### 全宽应用壳层

工作台采用全宽顶部导航、可折叠左侧栏、自适应主内容和可选右侧上下文面板：

```text
┌──────────────────────────────────────────────────────────────┐
│ 顶部导航：桌面 64px，移动端 56px                            │
├──────────────┬───────────────────────────┬───────────────────┤
│ 主侧栏       │ 主内容 / 编辑器           │ AI / 参考资料     │
│ 240px / 64px │ minmax(0, 1fr)            │ 320-384px，可收起 │
└──────────────┴───────────────────────────┴───────────────────┘
```

| 区域         | 移动端     | 桌面端                |
| ------------ | ---------- | --------------------- |
| 顶部导航高度 | 56px       | 64px                  |
| 顶部导航宽度 | `100%`     | `100%`                |
| 展开侧栏     | 抽屉 288px | 240px                 |
| 折叠侧栏     | 不适用     | 64px                  |
| 右侧面板     | 抽屉       | 320-384px，可完全收起 |
| 页面内边距   | 16px       | 24px，超宽屏 32px     |

不可破坏规则：

1. 顶部导航固定在视口顶部并横跨整个可用宽度。
2. 左侧栏从顶部导航下边缘延伸到视口底部，承载主导航、作品与章节树，不叠加第二个永久左栏。
3. 主内容只为可见导航、侧栏和右侧面板保留空间，并填满剩余区域。
4. 列表、工作台和画布不设置全局居中最大宽度；正文画布可以局部限制到约 760px。
5. 表格、时间线、树和画布的横向滚动必须局部化，页面壳层不能横向滚动。
6. 右侧面板关闭后不保留空白占位，关闭 AI 不影响写作。
7. 可调整面板提供键盘操作、最小与最大宽度，并能恢复默认尺寸。

### 壳层几何与滚动

- 顶部导航固定在视口顶部并横跨 `100%` 可用宽度。
- 侧边栏从顶部导航下边缘开始延伸到底部，不叠加第二个永久左栏。
- 主内容填满导航、侧边栏和可见上下文面板之外的剩余宽度。
- 关闭侧边栏或右侧面板后不保留空白占位。
- 表格、时间线、树、画布和宽内容只在自己的容器内横向滚动。
- 页面级容器必须设置 `min-width: 0`，避免长文本或表格把壳层撑出横向滚动。
- 常规业务页使用移动端 `16px`、桌面端 `24px`、超宽屏 `32px` 的页边距。

### 顶部导航

- 顶部导航保持单行，承载品牌、当前作品、必要的全局动作和账户入口。
- 触发器在导航中垂直居中，交互高度至少 44px。
- 下拉菜单上边缘紧邻导航下边缘，不覆盖导航，也不产生可见缝隙。
- 菜单通常与触发器右边缘对齐，并在视口边缘自动避让。
- 不使用负 `top`、负 margin 或 transform 把菜单推入导航区域。
- 导航和菜单的相邻边框不得叠加成明显的 2px 深线。

### 左侧栏与折叠浮层

- 展开态展示图标、标签、作品与章节层级；折叠态只保留必要导航图标。
- 折叠侧栏的二级浮层从侧栏右边界之外开始，边缘贴合但不相交。
- 浮层相对触发项垂直居中，并高于侧栏和页面内容。
- 同时通过 `hover` 与 `focus-within` 保持打开，支持键盘进入和退出。
- 外层允许浮层可见，内部滚动区使用 `overflow-x: hidden`，不得触发页面横向滚动。
- 桌面端折叠按钮为 `28x28px` 圆形图标按钮，圆心位于侧栏右边界线上，并从侧栏底部向上 `20%` 处；使用表面色、1px 边框和轻阴影。
- 折叠按钮悬停不改变尺寸，保持清晰焦点和可访问名称；展开态使用向左箭头，折叠态使用向右箭头；展开/折叠只改变侧栏宽度，按钮不横向漂移。
- 移动端侧栏变为抽屉时，折叠按钮改为抽屉右上角关闭按钮，不使用桌面端底部定位。

### 中央创作区

- 中央编辑区拥有最高视觉优先级，周围保留安静的 `canvas` 留白。
- 正文画布使用 `surface`，局部最大宽度约 760px，并随窄屏缩放。
- 工具栏按需出现，不长期挤压正文。
- 字数、保存状态、当前位置和同步状态属于低优先级信息，但必须可读。
- 专注模式可以隐藏顶部次要动作、折叠两侧面板，但必须保留退出入口和保存状态。

### 右侧上下文面板

- 用于 AI、人物、世界设定、资料和相关详情，内容按当前任务切换。
- 面板宽度为 320-384px，桌面端可并排，1024px 以下默认变为抽屉。
- AI 输出与作者正文在结构、标签和操作上明确分离。
- 面板切换不得重置未提交内容；关闭面板前处理正在编辑或生成的状态。

## 响应式规则

- `< 768px`：顶部导航高 56px；左侧栏变为 288px 抽屉；右侧上下文也使用抽屉；编辑器占满可用宽度。
- `768-1023px`：顶部导航高 64px；左侧栏可折叠；右侧面板默认变为抽屉；复杂多栏页面降为单栏。
- `>= 1024px`：启用完整壳层；左侧栏可在 240px 和 64px 之间切换；右侧面板可并排或收起。
- 360px 宽度下不得出现页面级横向溢出，320px 下核心写作和恢复操作仍可完成。
- 数据表在 768px 以下可以转换为分组列表；保留表格时只能让表格容器横向滚动。
- 固定底部操作区加入 `env(safe-area-inset-bottom)`，主内容预留对应空间。
- 使用动态视口单位处理移动浏览器地址栏变化，不用固定 `100vh` 制造跳动。

## 组件规范

### 按钮与图标按钮

- 标准按钮高度至少 44px，圆角 2px，文字 14px、字重 600。
- 主按钮每个区域最多一个，使用品牌强调色和高对比文字。
- 描边按钮使用表面背景和 1px 边框；幽灵按钮无常驻背景，悬停时使用轻激活底色。
- 图标与文字间距 8px。图标按钮必须有可访问名称和悬停提示。
- 危险按钮只用于不可逆操作，使用文字说明风险并要求明确确认。
- `hover` 只调整颜色或边框；`pressed` 可以使用不超过 1px 的短距离反馈，不改变布局。
- `disabled` 同时禁用事件、调整光标并降低视觉权重，但标签仍须可读。
- `loading` 保留原按钮宽度，显示进度文案并阻止重复提交，直到最新数据同步完成。
- 所有点击目标原则上不小于 44x44px。

### 输入框、选择器与文本域

- 输入框和选择器高度至少 44px；文本域最小高度 80px。
- 使用 2px 圆角、1px 边框、纯表面背景和无阴影默认态。
- 标签位于控件上方，占位符不能代替标签，已知值不能伪装成 placeholder。
- 聚焦时保持 1px 边框并切换为焦点色，同时提供清晰外轮廓，不引发布局抖动。
- 错误信息位于字段下方，说明具体原因和恢复方式。
- `disabled` 控件降低视觉权重并使用不可用光标，同时保持标签可读。
- `read-only` 保持正文对比度，通过只读说明或图标与可编辑状态区分。
- 自动保存显示“保存中”“已保存”“保存失败”或“存在冲突”，不能只显示旋转图标。

### 开关、单选和复选

- 开关建议为 44x24px，轨道使用 2px 圆角，滑块保持圆形。
- 开启态使用强调色轨道，关闭态使用中性表面和边框，并提供非颜色状态线索。
- 单选和复选命中区至少 44x44px，标签整体可点击。
- 单选圆点属于圆形语义例外；复选框使用 2px 圆角。
- 列表中的状态更新基于记录唯一标识，不能复用全局布尔值导致多行同步变化。

### 卡片、面板和统计块

- 面板使用表面色、1px 边框和 2px 圆角，不使用常驻重阴影。
- 通用内边距为 20-24px，移动端为 16px。
- 面板头部与正文使用一条分隔线或间距区分，不叠加额外阴影。
- 多个指标优先组成连续网格，通过 1px 分隔线建立整体，而不是每项单独悬浮。
- 空、加载和失败状态占据稳定内容区域，避免页面跳动。

### 表格与列表

- 表头高度约 42px，使用浅表面和 12px 半粗体文字。
- 记录行保持固定或稳定高度；长文本、悬停说明和操作数量不得撑高单行。
- 行悬停只改变背景色，不移动、不放大。
- 字段较多时由表格容器承担水平滚动，页面壳层不产生横向滚动。
- 操作表头和操作单元格水平居中。操作列吸附最右侧，使用不透明表面、左边框和正确层级。
- 桌面端可以使用紧凑图标操作；移动端优先使用更多菜单或操作抽屉。
- 分页横向排列并垂直居中，页码与翻页按钮保持同高。
- 实时检索的关键词输入默认使用约 300ms 防抖，不额外配置无价值的搜索按钮。
- 异步排序使用即时并发锁；边界按钮禁用，不重复堆叠边界错误提示。
- 空列表解释原因并提供一个明确的下一步，不使用装饰插画填充。

### 章节树与导航

- 使用缩进、展开状态、连接关系和选中状态表达层级。
- 主菜单、子菜单和章节行最小交互高度为 44px，选中区域使用一致可用宽度。
- 图标放入固定对齐盒，不为每个图标添加独立边框底板。
- 当前项使用高对比选中态并设置 `aria-current`，不能只靠文字颜色表达。
- 行操作在悬停和键盘聚焦时都可发现。
- 拖拽排序提供键盘替代操作，排序期间防止并发提交。
- 菜单文字通过 Flex 垂直居中，不用顶部内边距人工校准。

### 编辑器

- 工具栏按选择或任务出现，首版的选区操作不超过 5 项。
- 编辑器不得在 AI 返回后自动替换选区，也不得因侧栏切换丢失选择或草稿。
- 保存失败保留本地内容，提供重试、复制和冲突恢复方式。
- 重置视图只恢复缩放、滚动或布局状态，不删除正文和已保存数据。
- 当前编辑模式和工具通过高对比选中态、辅助文字与 `aria-pressed` 共同表达。

### AI 建议

- AI 内容使用独立面板或有标签的候选块，显示生成中、失败、完成和取消状态。
- 提供“插入”“替换”“复制”和“放弃”等显式动作。
- “替换”执行前展示影响范围，并支持撤销。
- 流式生成期间保持已有内容可读，避免布局持续跳动。
- AI 失败不能阻止用户继续写作，也不能清空用户输入或已有候选。

### 模态框、抽屉、下拉菜单与 Toast

- 模态框只用于需要中断、确认或保护焦点的任务，默认最大宽度约 512px。
- 抽屉用于窄屏导航、上下文详情或成组操作，桌面宽度通常不超过 384px。
- 下拉菜单使用 2px 圆角、1px 边框、表面色和轻微阴影，从关联壳层边界之外展开。
- Toast 通过 Portal 挂载到文档根节点，位于固定导航下方并高于其他界面层级。
- 错误 Toast 使用 `alert`，其他反馈使用 `status`；重复错误需要合并或抑制。
- 需要用户复制、阅读或确认的重要结果使用模态框或稳定面板，不使用短暂 Toast。
- 浮层打开后管理焦点、锁定背景滚动，并在关闭后把焦点归还触发器。
- 错误信息保留用户输入，并提供重试或恢复路径。

## 状态与异步交互

每个异步界面必须区分以下状态：

| 状态     | 设计要求                                       |
| -------- | ---------------------------------------------- |
| 首次加载 | 保留主要布局，使用接近最终内容形状的占位       |
| 后台刷新 | 不清空现有内容，使用低干扰进度提示             |
| 空结果   | 解释原因并提供一个主要下一步                   |
| 请求失败 | 显示人类可读原因，提供重试、返回或复制恢复路径 |
| 无权限   | 说明缺少的权限和可采取的下一步                 |
| 离线     | 保留可读与本地编辑内容，说明尚未同步的操作     |
| 禁用     | 保持标签可读，说明不可用原因                   |
| 只读     | 保持内容对比度，说明只读原因和恢复条件         |
| 保存冲突 | 保留双方版本，提供比较、复制和明确解决方式     |
| 部分成功 | 分别指出成功与失败对象，不用成功反馈掩盖失败   |

未知、加载、无结果、无权限和禁用状态不能统一显示为空白。

异步按钮必须显示处理中状态、阻止重复提交、保留原按钮尺寸，并在失败时保留用户输入、当前选择和已加载内容。

## 状态设计

### 账户、语言与品牌资源

- 登录页使用一个标识输入框，支持用户名、邮箱或完整 E.164 手机号；错误文案不能暴露账号是否存在。
- 注册入口由公开站点配置控制，关闭时不显示；前端隐藏不替代服务端校验。
- 语言切换提供简体中文、繁體中文和 English，使用 `zh-CN`、`zh-TW`、`en-US`，缺失键回退 `zh-CN`。
- Web 顶部 Logo 是管理员配置的全局资源，不与用户头像混用；Desktop Logo 固定在安装包中，不展示配置入口。
- 头像与 Web Logo 上传控件在选择后立即显示 5 MiB 上限、支持格式、预览和失败恢复。头像提示最大 2048×2048 与 4,194,304 像素，Logo 提示最大 4096×4096 与 16,777,216 像素。
- URL 头像输入只接受 HTTPS 绝对 URL，并在客户端提前拒绝 userinfo、`localhost`、环回地址和字面量私网 IP；图片请求使用 `referrerPolicy="no-referrer"`，加载失败显示默认头像。

### Skill 管理状态

- Web Skill 列表提供上传、名称搜索、启用筛选和分页；行操作包含详情、启用/禁用、编辑 `SKILL.md` 和删除。
- 上传界面明确显示 `.zip` / `.skill`、10 MiB 压缩、50 MiB 解压和 500 文件限制，并把结构、路径或大小错误关联到本次文件。
- 详情页优先展示名称、说明、启用状态、当前版本、哈希和校验结果；文件清单不提供脚本执行入口。
- 删除使用二次确认。`deleting` 状态从普通列表隐藏，在管理反馈中保持可查询且不可重新启用。
- Desktop Skill 页面只显示列表、详情、重新扫描和启用/禁用；不得渲染上传、编辑、删除、移动或重命名操作。
- Desktop 内容变化、超限或任务前复核失败时立即切换为禁用，并提供“重新查看后启用”的恢复路径。

每个异步界面都要设计以下状态：

| 状态     | 设计要求                                       |
| -------- | ---------------------------------------------- |
| 首次加载 | 保留主要布局，使用与最终内容形状接近的占位     |
| 后台刷新 | 不清空现有内容，使用低干扰进度提示             |
| 空结果   | 解释原因并给出一个主要动作                     |
| 请求失败 | 使用人类可读文案，提供重试、返回或复制恢复路径 |
| 无权限   | 说明缺少的权限和可采取的下一步                 |
| 离线     | 保留可读与本地编辑内容，明确哪些操作尚未同步   |
| 禁用     | 保持标签可读，说明不可用原因                   |
| 只读     | 保持内容对比度，明确只读原因与恢复条件         |
| 保存冲突 | 保留双方版本，提供比较、复制和明确的解决方式   |
| 部分成功 | 指出成功与失败的对象，不用成功 Toast 掩盖失败  |

未知、加载、无结果和无权限是不同状态，不能统一显示为空白或 `-`。

## 层级与浮层

| 层级           | z-index    | 对象               |
| -------------- | ---------- | ------------------ |
| 页面内容       | `auto / 0` | 编辑器、面板、表单 |
| 吸附表格单元格 | `10 / 20`  | 正文、表头、操作列 |
| 固定底部操作区 | `50`       | 移动端操作或导航   |
| 固定侧栏       | `55`       | 桌面侧栏           |
| 顶部导航       | `70`       | 全宽导航           |
| 菜单浮层       | `80`       | 下拉与折叠菜单     |
| 抽屉及遮罩     | `200`      | 导航与上下文抽屉   |
| 模态框及遮罩   | `300`      | 对话框             |
| Toast          | `10000`    | 全局即时反馈       |

新浮层必须先归类再复用现有层级。不得通过不断增加更高数值解决遮挡问题。

## 动效与性能

- 常规颜色、悬停和按压反馈使用 120-180ms。
- 壳层宽度、菜单和面板展开使用 180-200ms `ease-out`，最长不超过 240ms。
- 只动画 `transform` 和 `opacity`，不动画会频繁触发布局的宽高和位置属性。
- 动效只用于反馈、层级和状态变化，不加入滚动劫持、视差、持续漂浮和装饰性循环。
- 自动保存和 AI 流式输出不得触发大面积动画。
- 在 `prefers-reduced-motion: reduce` 下关闭非必要动画，将布局切换降级为即时变化。
- `will-change` 只用于即将动画的元素，动画完成后移除。
- 图片、字体和异步区域预留尺寸，避免布局偏移。

## 图标、图像与文案

### 图标与图像

- 一个界面只使用一套图标家族，当前 Web 端统一使用 `lucide-react`，线宽统一为 1.5-2px，不混用填充与线框体系。
- 使用项目已经安装的图标库，不手绘业务 SVG 图标；新增依赖前先检查现有依赖和需求。
- 常用动作同时依靠位置、标签或提示，不让生僻图标独自表达含义。
- 产品界面不依赖库存照片。封面、人物和参考图属于作品内容，不属于界面装饰。
- 状态点只用于真实状态，不能作为每个列表项的装饰。

### 文案语气

- 使用平静、直接、尊重作者选择的中文。
- 首选“保存失败，请重试”，避免夸张、卖萌或责备用户的语气。
- AI 操作用“建议”“生成候选”“应用”，避免暗示模型替作者决定。
- 按钮使用明确动词，例如“创建作品”“保存草稿”“插入正文”。
- 同一动作在导航、按钮和菜单中使用一致名称，不为同一意图创造多个近义标签。
- 示例数据必须标明是示例，不用虚构的精确数据制造真实感。

## 界面生成与定制

### 全局生成语言

用于设计稿或生成式界面工具的基础约束：

> 设计一个面向小说作者的高频创作工作台。使用克制、专业、低装饰的扁平化语言，沿用 xnovel 语义颜色，采用纯色表面、1px 细边框和统一 2px 矩形圆角。通过排版、间距、选中态和边界建立层级，不使用渐变、玻璃拟态、厚阴影、大圆角卡片或装饰性动效。顶部导航横跨视口，左侧栏可折叠，主内容填满剩余宽度，右侧 AI 与参考面板可收起。AI 内容必须与作者正文清晰分离。

### 列表页生成约束

> 页面顶部包含标题、简短说明和一组主操作；下方是可换行的实时筛选区和全宽列表或数据表。记录保持稳定高度，长文本单行省略并可通过鼠标和键盘查看全文。字段较多时只让表格容器水平滚动，操作列吸附最右侧并居中。移动端转换为分组列表或更多操作抽屉。

### 表单页生成约束

> 使用清晰的单列或响应式双列表单。标签始终位于字段上方，输入框和按钮高度至少 44px，使用 2px 圆角和 1px 边框。聚焦不改变边框宽度，错误信息紧邻字段并说明恢复方式。提交区保持稳定，不使用超宽模态框承载完整编辑任务。

### 工作台壳层生成约束

> 顶部导航占全部可用宽度并固定；侧栏从导航下边缘延伸到底部。折叠侧栏浮层从侧栏右边界开始，不重叠、不留缝，不产生页面水平滚动。主编辑区填满剩余空间，正文画布局部限制阅读宽度；右侧上下文面板可以收起，并在 1024px 以下变为抽屉。

### 生成后检查

- 顶部导航是否真正横跨整个可用宽度？
- 主内容是否填满导航、侧栏和可见右侧面板之外的空间？
- 所有矩形组件是否统一为 2px 圆角和 1px 默认边框？
- 是否沿用 xnovel 语义颜色，没有引入新的外部主题色？
- 表格横向滚动时，操作列是否仍固定在最右侧？
- 折叠侧栏浮层和顶部导航下拉是否贴边但不相交？
- 加载、空、失败、离线、禁用、只读和处理中状态是否完整？
- AI 候选与作者正文是否明确分离，并需要作者确认才能应用？
- 360px 宽度是否无页面级横向溢出？
- 键盘焦点、可访问名称、状态文字和减少动效支持是否完整？

### 定制与所有权

可以替换：

- 语义颜色令牌的具体色值，但必须作为一次完整品牌决策成组修改。
- 标题字体、Logo、封面、人物图和作品素材。
- 页面导航结构、业务字段和真实领域组件。
- 在可读性允许范围内调整内容密度。

不得随主题或单个页面改变：

- 语义颜色角色及其状态含义。
- 44px 控件基线、焦点行为、2px 矩形圆角和命中区。
- 应用壳层、浮层锚点、表格稳定性和局部滚动规则。
- 作者对正文的控制权，以及 AI 内容的候选性质。
- 键盘、屏幕阅读器、对比度、窄屏和减少动效支持。

## 无障碍基线

## 控制台壳层

- 顶部导航下方使用单一永久左侧栏，不叠加第二个永久左栏。
- 侧边栏展开宽度约 `240px`，收起后保留图标、焦点名称和可访问提示。
- 普通用户只显示工作台和账户菜单；管理员额外显示用户与审计日志入口。
- 审计日志作为可展开菜单组，子项为登录日志和操作日志。
- 小于 `768px` 时侧边栏变为抽屉，导航后自动关闭，Escape 关闭后焦点返回触发按钮。
- 未实现的 AI 模型、用户和审计页面必须显示明确占位，不展示虚构统计或不可用操作。
- 首次强制改密期间不渲染控制台壳层，其他路由重定向到改密页面。
- 侧边栏、抽屉和菜单项保持至少 `44px` 命中区，当前路由使用 `aria-current="page"`。
- 侧栏折叠按钮使用 `ChevronLeft` / `ChevronRight` 表达展开与收起方向；可展开菜单组使用 `ChevronRight` / `ChevronDown` 表达收起与展开状态。
- 侧栏折叠按钮与菜单组方向图标统一使用 `18px` 图标尺寸。
- 方向图标颜色继承当前主题语义色，不复制外部参考图的固定色值；移动端关闭抽屉继续使用 `X` 图标表达关闭语义。

- 所有功能支持键盘操作，焦点顺序与视觉顺序一致。
- 焦点指示器始终可见，不以移除 `outline` 作为视觉优化。
- 正文、控件、占位符、辅助文字和状态文字满足 WCAG AA 对比度。
- 表单、对话框、菜单、标签页和树结构使用正确语义与可访问名称。
- 屏幕阅读器能获知保存结果、请求错误、AI 生成进度和面板展开状态。
- 当前导航使用 `aria-current`，切换按钮使用 `aria-pressed`，动态反馈使用适当的 `status`、`alert` 或 `aria-live`。
- 抽屉和模态框具有焦点陷阱、Escape 关闭能力和正确的焦点归还。
- 页面在 200% 缩放、320px 宽度和仅键盘环境下保持可操作。
- 颜色、位置和图标都不能成为传达状态的唯一方式。

## 设计验收清单

完成界面前确认：

- 中央创作区保持主导，应用壳层没有无理由的大面积空白。
- 顶部导航、可折叠侧栏、自适应主内容和右侧上下文面板符合规定尺寸与断点。
- 使用既有颜色和间距令牌，没有随意新增颜色、圆角或层级值。
- 所有矩形组件为 2px 圆角；只有明确的圆形语义元素保持圆形。
- 按钮和输入至少 44px 高，交互目标原则上不小于 44x44px。
- 加载、空、失败、离线、禁用、只读、冲突和窄屏状态已经处理。
- 鼠标、键盘和触摸都可以完成核心写作与恢复操作。
- AI 内容与作者内容清晰分离，应用建议需要明确确认并可撤销。
- 表格和宽内容只在局部滚动，360px 宽度无页面级横向溢出。
- 浮层锚点、焦点管理、z-index 和安全区处理正确。
- 没有不必要的渐变、阴影、卡片、动画或装饰图标。
- 文案准确直接，没有含糊动作、虚构数据或重复动作名称。
- 新增的稳定视觉模式已经补充到本文。
